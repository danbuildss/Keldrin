# Operations and incident runbook
Proposed runtime: GitHub Actions/Aeon orchestrates bounded research jobs; TypeScript worker and Supabase store; REST via compatible host, Vercel candidate; UI only after backend proof. Confirm costs, region, quotas and runtime constraints. Cron is not a streaming feed. Use explicit environment variables, no default production credentials.

Set up separate repo and environment; run local tests; verify migrations in disposable DB; approve one real job; confirm private logs and source permissions; use staging; confirm kill switches; approve production. Monitor last successful fetch, verification lag, queue depth, stale observations, schema failures, cost/run and delivery errors. Alerts private first; Telegram optional with founder approval. Outage: pause source, mark unavailable/stale, do not silently serve old data as current, retry boundedly, reconcile and record recovery. Rollback: disable worker/paid routes, revert deployment, keep evidence and migrations reversible or forward-fix documented. Corrections: mark affected revision superseded/withdrawn, expose correction reference, draft public explanation for approval.

Session closure: log date/commit, tasks, files, test results, actual costs, failures, decisions requested, next action. Preserve Notes.MD. Do not call unverified tests passed. See memory/journal.md and templates/SESSION.md.
